Windows installer handoffs split arguments that contain spaces

Windows installation and argument forwarding

Failure mode

Both the UAC relaunch and final downloader launch pass arrays to Start-Process without quoting each Windows command-line argument. Start-Process joins the array into a command line; paths containing spaces can arrive as multiple arguments. The default machine install root contains Program Files, so the installed script path itself includes a space.

Evidence or rationale

Observed in install-bootstrap.ps1:140-159 and 544-549. Get-DefaultInstallRoot builds the path from ProgramFiles at lines 214-225. tests/install-bootstrap-security.ps1:183-237 mocks Start-Process and checks a joined string, so it does not exercise the child process parser. A temporary PowerShell 7.6.6 child-process probe reproduced a path with spaces arriving as separate arguments.

Why this matters

A routine install can copy files successfully and then fail to start the installed script. Elevation can also lose ScriptDir, InstallRoot, ShortcutDir, or forwarded values. An input-file path with spaces can be changed before it reaches the downloader, creating a failure that is hard to diagnose from the installer summary.

Recommended mitigation

Serialize every argument with Windows-compatible quoting before passing a single command-line string to Start-Process, or use a supported process API that preserves individual argument boundaries on every host the repository supports. Cover the PowerShell 5.1 and PowerShell 7 branches. Keep the validated host, working directory, and shortcut behavior.
